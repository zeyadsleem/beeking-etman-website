1. نظرة عامة على المشروع

مملكة النحل (Beeking Etman) هو متجر إلكتروني عربي first للعسل الطبيعي ومستلزمات تربية النحل. يتضمن كتالوج منتجات، مختبر خلط العسل التفاعلي (/blends)، سلة تسوق بكوكيز موقّع، صفحة checkout مع دفع وهمي (بدون بطاقة حقيقية)، حسابات اختيارية، ودعم كامل للغتين العربية والإنجليزية.

المشروع مبني على Svelte 5 (runes) مع SvelteKit 2 ويعمل على Cloudflare Pages مجاناً بالكامل ($0/شهر).

RTL Arabic-first Bilingual (AR/EN) Free Tier Hosting Interactive Blend Lab Full Admin Dashboard

3. الميزات الرئيسية

المتجر (Storefront)

  • كتالوج منتجات مع variants (أحجام/أنواع مختلفة)
  • بحث FTS5 بالعربية والإنجليزية مع autocomplete
  • فرز وتصفح (12 منتج/صفحة)
  • صفحة منتج تفصيلية مع معرض صور
  • عرض الأسعار بالجنيه المصري (أرقام عربية أو إنجليزية حسب اللغة)

سلة التسوق (Cart)

  • سلة client-side مع مزامنة عبر كويكيز موقّع (HMAC, HttpOnly)
  • شحن ثابت 60 ج.م / مجاني فوق 600 ج.م
  • مزامنة السلة عبر التبويبات (storage listener)
  • دعم خلط العسل كعنصر واحد في السلة

صفحة الدفع (Checkout)

  • إدخال بيانات الشحن مع تحقق zod
  • دفع وهمي (mock payment) — لا تُجمع بيانات بطاقات حقيقية
  • Idempotent order creation عبر nonce
  • صفحة نجاح مع كويكيز موقّع للوصول
  • فواتير PDF قابلة للتحميل

مختبر الخلط (Blend Lab — /blends)

  • واجهة خلط تفاعلية خفيفة (DOM mix UI) بمؤثرات صوتية Web Audio
  • 5 أهداف ( الطاقة، المناعة، الصحة العامة، العناية بالبشرة، الهضم)
  • 5 أنواع عسل أساسية + 5 مضافات
  • حساب تكلفة تلقائي من قاعدة البيانات
  • فن procedural كامل (بدون ملفات ثابتة)
  • دعم reduced-motion + وصول بديل (sr-only action bar) لقارئات الشاشة و E2E

الحسابات (Accounts)

  • تسجيل دخول / إنشاء حساب بـ Better Auth
  • صفحة ملف شخصي (الاسم، كلمة المرور، تسجيل الخروج)
  • عناوين الشحن المحفوظة (حتى 10 عناوين)
  • طلبات سابقة مع تفاصيل

الدعم اللغوي (i18n)

  • عربية (RTL) بشكل افتراضي + إنجليزية
  • كشف لغة المتصفر من Accept-Language header
  • كتالوج ثنائي اللغة (name + name_en)
  • تنسيق عملة حسب اللغة

لوحة التحكم (Admin)

  • لوحة إحصائيات (إيرادات، طلبات، عملاء، منخفضي المخزون)
  • إدارة الطلبات مع حالات وتحديث المخزون
  • إدارة المنتجات (إنشاء، تعديل، variants، رفع صور)
  • إدارة التصنيفات
  • سجل التدقيق (audit log)
  • إدارة وسائط الصور
  • تصدير الطلبات CSV

الأمان (Security)

  • Rate limiting DB-backed (login: 10/60s, register: 5/1h)
  • Guard على admin routes (role check server-side)
  • Kosy موقّع (HMAC) للسلة والطلبات
  • Validation على كل الإدخالات (zod)
  • No card data collection (mock payment)
  • Boot-time env validation

8. نقاط القوة

معمارية أمان تجربة مستخدم تكلفة صيانة
  • $ 0/شهر — مجاناً بالكامل: Cloudflare Free tier يكفي تماماً لموقع بهذا الحجم. لا تكاليف خفية.
  • عمليات صارمة على الأموال: الأسعار تُحسب من قاعدة البيانات عند الطلب (مش من الكوكيز)، والمدفوعات وهمية — لا خطر تسرب بيانات بطاقات.
  • Security-first: Rate limiting DB-backed، guard على admin routes (layout + action)، Kosy موقّع، zod validation على كل الإدخالات، boot-time env validation.
  • Bilingual RTL: دعم كامل للعربية والإنجليزية مع RTL تلقائي، كتالوج ثنائي اللغة، تنسيق عملة حسب اللغة.
  • Blend Lab: تجربة تفاعلية فريدة بمحرك خفيف (DOM + صوت Web Audio) تضيف قيمة تنافسية للمتجر.
  • Admin Dashboard شامل: إحصائيات، إدارة طلبات/منتجات/تصنيفات، سجل تدقيق، رفع صور.
  • Clean Architecture: فصل واضح بين المنطق النظيف (lib/) والخدمات (server/) والعرض (routes/components).
  • Testing متكامل: Vitest للوحدات + Playwright لـ E2E، مع صور procedural لل blend lab.
  • Edge-first: D1 + KV + Pages كلها edge — أداء سريع عالمياً.
  • Content Protection: منع فتح الصور في تبويب جديد + منع السحب.
  • View Transitions: انتقالات سلسة بين الصفحات بدون ومض أبيض.
  • Idempotent Orders: نظام nonce يمنع تكرار الطلبات.

9. نقاط الضعف والملاحظات

محدودية تقني تجربة تنبيه
  • Dev server لا يعمل hydration: vp dev يقدم HTML بدون سكريبتات client-side، مما يعني أن السلة والدفع لا تعملان في وضع التطوير. يجب استخدام pnpm run build && pnpm run preview لأي شيء تفاعلي.
  • لا نظام دفع حقيقي: الدفع وهمي فقط (mock payment). لا يوجد تكامل مع بوابات الدفع الفعلية (PayPal, Stripe, مصر للدفع الإلكتروني).
  • لا إدارة مخزون متقدمة: لا يوجد تنبيهات مخزون منخفض تلقائية، لا تاريخ مخزون، لا دعم Multi-warehouse.
  • لا تصنيفات فرعية متقدمة: الهيكل يدعم parent_id لكن لا يوجد UI لتصنيفات متعددة المستويات.
  • لا إشعارات بالبريد: إرسال البريد best-effort و/fire-and-forget — لا يوجد تأكيد وصول.
  • لا CDN للصور: الصور مخزنة في KV وتُقدم من Edge لكن لا يوجد transform/on-the-fly resize.
  • لا مراجعات/تقييمات منتجات: لا يوجد نظام مراجعات أو تقييمات من العملاء.
  • لا کuponات أو خصومات: لا يوجد نظام كوبونات أو عروض ترويجية.
  • لا شحن حقيقي: شحن ثابت (60 ج.م) بدون تكامل مع شركات الشحن أو حساب الوزن/المسافة.
  • لا تتبّع للأرباح: لا يوجد dashboard لتتبع أرباح/churn/متوسط قيمة الطلب على المدى الطويل.
  • SQLite محدود: D1 Free tier له حدود (5M reads/day، 100K writes/day) — قد يكفي لكنه ليس للنمو الكبير.
  • دعم محدود لـ Multiple Admin users: يدعم عدة admin لكن آلية bootstrap تعتمد على ADMIN_EMAIL واحد فقط.
  • لا يوجد SOPA: لا يوجد تعليق/"archive" للمنتجات — فقط حذف.
  • High coupling to Cloudflare: المشروع مقترن بشدة بـ Cloudflare (D1, KV, Pages) — ترحيل لمنصة أخرى يتطلب إعادة هيكلة.

scalability notes

  • FTS5 search on D1 works well at current scale but may need external search (Algolia/Meilisearch) for large catalogs.
  • No server-side rendering for product images — all served from KV with immutable caching (good but no transforms).
